# Linx experimental native NPU and CPU-SIM backends

[中文](README_zh.md)

The native backend is a **restricted experimental integration**. Known unsupported
paths fail compilation with `PTO Linx experimental:` and a reason. See the
[instruction matrix](../../../../docs/linx-tile-instruction-support.md) before
selecting a profile. Functional-model tests are not physical NPU validation.

Linx is an independent backend selected through `<pto/pto-inst.hpp>`. Its API is
the native Linx TileOP API, including its original namespace placement, argument
order, overloads, defaults, hardware formats, and legality checks. Selecting
Linx does not translate Ascend instruction calls into Linx calls.

## Source and maintenance

`impl/` imports the device backend and its common dependencies from
[LinxISA/Linx-TileOP-API](https://github.com/LinxISA/Linx-TileOP-API/tree/74d7326c521aeb1b21c52602b67c55b42b3563a3),
default branch `linx`, revision `74d7326c521aeb1b21c52602b67c55b42b3563a3`.
The 21 original header hashes are recorded in
[upstream.json](../../../../tests/cpu/linx/upstream.json). Source formatting and
attribution are preserved. Imported headers carry the standard PTO-ISA CANN
license notice, following the repository header convention. The manifest hashes
refer to the original upstream files before that comment-only addition.

The allowed device-side changes are the repository license notice, relocated
include paths, prefixed header guards, backend selection and marked admission
guards generated by `sync_linx_headers.py`. CPU selectors
share the native Tile, region, and hardware-format declarations while substituting storage and
execution. A CPU-only deferred type lookup prevents GCC from eagerly
instantiating an unrelated Local assembly overload for explicit Shared TLOAD
template arguments. Valid carrier types are unchanged. Device assembly and
native legality checks are unchanged; unsupported device paths now add an
explicit rejection. There is no guard-bypass macro.

Three CPU headers (`native_api.hpp`, `region.hpp`, `predicate.hpp`) are generated
from these native declarations. It first strips only marked device admission
guards, retaining all upstream legality checks. The generator replaces assembly emitters and
compiler-only carriers, preserving the declarations and validation around them.
It fails on unmapped assembly; there is no success-returning instruction stub.
`TPREFETCH` has no value result; CPU-SIM does not model a device cache.

```bash
python3 tests/script/sync_linx_headers.py
# Also compare the import against the pinned upstream checkout:
python3 tests/script/sync_linx_headers.py --upstream /path/to/Linx-TileOP-API \
    --inventory /tmp/linx-inventory.json
# Explicit regeneration after reviewing an emitter change:
python3 tests/script/sync_linx_headers.py --write
```

Do not hand-edit generated declarations. For a future upstream update, review
the source revision and manifest together with all newly encountered emitters.
The native support constraints, including retired instruction rejections, are
part of the backend contract.

## Build and launch

Use a C++20-or-later compiler and the repository's `include/` directory. The
native Linx target predefines `__linx`, selecting `PTO_NPU_ARCH_LINX` automatically.
An explicit `PTO_NPU_ARCH_LINX` still requires that compiler target. Existing
Ascend and cost-model flags cannot be combined with Linx flags.

```bash
# Device object; use the native Linx toolchain and its normal linker/runtime.
linx-clang++ -std=c++20 -mlxbc -O2 -I include -c kernel.cpp -o kernel.o

# Same kernel source and instruction calls, CPU execution.
g++ -std=c++20 -O2 -ffp-contract=off -pthread -I include \
    -D__CPU_SIM -DPTO_CPU_SIM_TARGET_LINX kernel.cpp host.cpp -o kernel-test
```

CPU-SIM requires a little-endian LP64 host. Keep fast-math disabled and floating
contraction off: reduction order and separate matrix product/accumulation
rounding are observable. No CANN dependency or additional library is required
for Linx-only builds. Existing packaging installs the entire `include/` tree,
including both backends; no second packaging path is introduced.

A single-PE host invocation observes `get_thread_idx() == 0`. Launch kernels
using multiple PE contexts, Shared matrix operands, or peer `GMOV` with:

```cpp
pto::linx_cpu::runCore([&] { kernel(input, output); });
```

The default host launcher executes four PE contexts. `CoreConfig{peCount, memory}`
selects one to four workers and optional GM address mappings. `syncCore()` is a
reusable barrier across the active workers; worker exceptions and divergent
barriers wake waiting peers and propagate to the caller after all workers join.
Shared producers rendezvous with the PEs selected by their
mask; singleton producers do not wait for nonselected PEs. `GMOV` requires all
four source participants even with a subset destination mask; a single-PE launch
also admits self movement. Participating PEs
must issue the corresponding operations in the same order. Per-PE GM pointers
use the original `get_thread_idx()` API. A missing selected participant causes
a CPU error; there is no arbitrary execution-time limit. Shared allocations live
for the worker's invocation; prefer `runCore` for repeated Shared kernels.
Absolute Shared slots are visible to every PE, including consumers that did not
execute their producer. A plain Shared load uses a singleton producer; multiple
producers require explicit assembly ranges under the native contract.

Explicit slots retain ordered publications separately from each PE's consumption
position. Acquiring a slot selects the next publication for that PE, so a fast
producer cannot overwrite a delayed consumer's input. Copy a Shared handle to
reuse an acquired generation. Publications are reclaimed after all active PEs
consume them, or when the launch ends. This models the tested producer/consumer
protocol; it does not add TPUSH/TPOP or model bounded hardware FIFO backpressure.

Device-address examples must supply backing storage explicitly:

```cpp
std::vector<std::byte> storage(4096);
std::array<pto::linx_cpu::MemoryRegion, 1> regions{{{0x10000, storage}}};
pto::linx_cpu::runCore([&] { kernel(); }, {4, regions});
```

Tile GM accesses translate mapped addresses and check access bounds. Unmapped
ordinary host pointers retain host semantics; low addresses require a mapping.
Mappings and their storage must outlive `runCore`. Overlapping or wrapped address
ranges are rejected. Scalar C++ dereferences do not undergo automatic translation;
use `globalAddress(pointer, offset, length)` in a host adapter for those accesses.

## Simulation contract

The CPU implementation uses the native descriptors and validates physical
capacity, valid shape, subview extent, assembly writer extent, indexed byte
ranges, and atomic alignment. It models M16/M32/N8 storage, M32 B64 low/high
planes, packed four-bit lanes, Predicate CELLs, Local assembly order, Shared
INIT/MIDDLE/LAST publication, peer moves, and Shared matrix slots. Instruction
inputs are captured before output publication where native aliasing permits it.
Atomics serialize competing host updates and return the observed old value.

Numeric execution includes native scalar and packed conversions, rounding
modes, signed integer wrapping, BF16 operations, vector/reduction operations,
FP32-ordered matrix accumulation, MX scales, CScale, quantization/activation,
and reductions over final encoded matrix outputs. The reference rules are
based on [PTO-ISA/pto-spec](https://github.com/PTO-ISA/pto-spec/tree/42067d0f2890b8c013a868bd1247ebc6437b3179).
In particular, TGATHER/TSCATTER use row indices; GM indexed operations and
atomics use signed byte displacements. These APIs are not interchangeable.
`MGATHER_MASK` and `MSCATTER_MASK` consume canonical U8 lanes containing 0 or 1.
They do not consume the packed-bit carrier produced by RowMajor TCMP/TCMPS.
CPU-SIM checks indexed mask bytes and preserves inactive scatter destinations.

The following deliberate relaxations allow device-invalid programs to run on
the host; callers must not rely on them for device legality:

- Total hardware register/Shared capacity, scheduling, bank conflicts, and
  instruction timing are not modeled. Per-Tile descriptor capacity is checked.
- CPU Local carriers start at zero. Full hardware generation-definedness and
  every forbidden input/output alias are not tracked; `Null` padding is not a
  portable promise about its value. Shared publication and assembly overlap
  are checked explicitly.
- Host memory replaces device address translation, memory domains, cache events,
  and restart/fault behavior. Prefetch does not probe device permissions.
  Concurrent atomic results follow one legal host serialization, not a fixed
  device scheduling order. Floating sticky status registers are not exposed.
- The active native surface has no TPUSH/TPOP FIFO API. No Ascend FIFO protocol
  or unsupported instruction is synthesized for Linx.

Host transcendental functions supply numeric evaluation. TLOG rounds log2 and
the multiply by ln(2) separately. TEXPDIF rounds its intermediate SUB before
EXP, including same-type FP16/BF16; widening forms subtract in FP32.
TRSQRT follows the pinned model: typed SQRT then DIV, including FP16/BF16.
The pinned specification instead uses high-precision reciprocal square root
before final encoding. This specification discrepancy remains open; CPU-SIM
model parity must not be presented as full specification conformance.
Activation preserves the model's signed zero for finite negative inputs. Local
tests check prescribed finite results, raw format encodings, rounding boundaries,
non-finite cases, and operation ordering; they are not an
exhaustive proof of bitwise agreement with every hardware implementation.

## Validation

```bash
CXX=g++ python3 tests/run_cpu.py --testcase linx_native --verbose
python3 tests/cpu/test_linx_native.py --compiler g++ \
    --output-dir /tmp/linx-check --sanitize --release
python3 tests/cpu/test_linx_native.py --compiler g++ \
    --linx-compiler /path/to/linx-clang++ \
    --upstream /path/to/Linx-TileOP-API --survey \
    --output-dir /tmp/linx-device-check
```

Use a fresh output directory. `result.json` records exact commands, compiler
assessment, exits, diagnostics, and individual log paths. The optional survey
compares the original native checkout, the relocated device backend, and
CPU-SIM. Upstream-invalid fixtures are reported separately, not counted as
successful instruction execution tests. Deliberate experimental rejections
are also reported separately from native-valid fixtures.

The survey checks the baseline's resolved header path and demotes the native
compiler's automatically injected SDK include directory. This ensures that the
comparison uses the pinned checkout rather than the toolchain's bundled copy.

The fixtures cover scalar formats and rounding; vector/scalar/row/column
operations; Predicate and TileArray regions; layout transport and assembly;
Core4 moves and Shared publication; local/Shared/MX/GEMV matrix operations;
image and weight packing; Shared slots; indexed memory and atomic operations;
and compilation/runtime rejection cases. The standalone suite checks device
syntax and assembly; the separate model runner executes the same kernels through
both the original and imported native headers:

```bash
python3 tests/cpu/test_linx_models.py --compiler g++ \
    --linx-compiler /path/to/linx-clang++ \
    --model-root /path/to/SuperScalarModel \
    --upstream /path/to/Linx-TileOP-API \
    --output-dir /tmp/linx-models --jobs 4
```

Build `gfrun` following [SuperNPUBench's model instructions](https://github.com/PTO-ISA/SuperNPUBench#running-on-the-models)
and [SuperScalarModel](https://github.com/LinxISA/SuperScalarModel). This runner
uses the documented LinxV5 Clang 15 target and startup ABI. It links target libc
without libc++; `--runtime-dir` can select compatible target runtime libraries
when the installed bundle contains libraries for another host architecture.
It sets one or four model PE contexts for each case, exports guest result memory,
and checks every result and trailing canary against an independent golden. CPU
and model outputs must also agree byte for byte. Reaching the model's exit with
`R2 = 0` alone is insufficient. `--case NAME` selects a focused reproducer.

The default model suite audits 151 ordinary instruction API names, 11 `_U`
forms and 64 `_ASS` forms. Both preprocessed entry-point catalogs must match.
CPU passes 151/151 ordinary names and 226/226 including wrappers. Native passes
109/151 ordinary names and 121/226 including wrappers, requiring every assigned
profile to pass. Four helpers, 32 retired names and lowercase utilities are
separate; these are API-name counts, not architectural opcode counts.

The 229 profiles yield 229 CPU passes. Unguarded native and original upstream
both pass 122 and fail 107. Restricted native executes those 122 successfully
and explicitly rejects the 107 known failing profiles. Partial instruction
support and rejection never count as complete numerical passes. `--legacy-cases`
replays the historical 130-case suite; `--case NAME` selects a profile.

`result.json` and `instruction-matrix.json` preserve commands, source/golden
hashes, exits, model diagnostics and profile ownership. Full numerical auditing
returns nonzero for rejected/failing profiles. Separately verify admission with:

```bash
python3 tests/cpu/test_linx_admission.py \
  --baseline /tmp/unguarded-instructions/result.json \
  --restricted /tmp/restricted-instructions/result.json \
  --output-dir /tmp/linx-admission --jobs 8
```

This checks all known native failures are blocked and all admitted profiles pass,
then verifies rejection at `-O0/-O2` with `NDEBUG` and public/direct includes.
Template guards reject before backend lowering. A few non-template scalar aliases
use an error attribute and stop before their retained assembly. Admission requires
a clear diagnostic without a compiler crash. Syntax-only checks cannot validate
all auxiliary guards.
Use a separate unguarded snapshot via `--device-include` only for diagnostics;
there is no supported product flag that enables blocked instructions.

The [support matrix](../../../../docs/linx-tile-instruction-support.md) records
exact restrictions and upstream reports. The [review record](../../../../docs/linx-integration-review.md)
explains changes, numerical contract and regression scope. Restore a path only
after a repaired pinned dependency combination passes its independent execution
profiles; an upstream issue being closed is insufficient.
